# AutoISF 3.2.1 — учебная программа лаборатории

## Назначение и границы

Материал предназначен для обучения чтению исходного кода и проверке алгоритмической логики AutoISF. Все упражнения выполняются на синтетических входных данных.

Запрещено использовать результаты упражнений для изменения реального профиля, помпы, CGM, Nightscout или параметров терапии. Диапазоны UI — ограничения интерфейса/хранения, а не клинически рекомендованные диапазоны. Нулевые значения по умолчанию не являются рекомендацией включать веса.

### Схема потока

```text
Настройки и профиль (в лабораторном разборе — только фиктивные)
                 |
                 v
OpenAPSAutoISFPlugin
                 |
                 +---- проверка наличия профиля / статуса глюкозы / ограничений
                 |
                 v
DetermineBasalAutoISF / autoISF calculation
                 |
                 +---- входные данные и временные ряды
                 +---- расчёт факторов AutoISF
                 +---- ограничение итогового коэффициента
                 |
                 v
APSResult / диагностические факторы
```

Схема концептуальная: точные вызовы и порядок необходимо подтвердить по исходному коду конкретного commit, а не по названиям классов.

### Ключевой принцип

Не смешивать четыре разных уровня:

- **Вход:** измерения, профиль и вычисленные upstream-показатели.
- **Условия допуска:** проверки наличия и качества данных, временные gates.
- **Факторы:** математические множители AutoISF.
- **Ограничение/выход:** min/max и дальнейшие ограничения алгоритма.

Если фактор не прошёл gate, это не то же самое, что фактор равен нулю по результату формулы. В первом случае вычисление фактора пропущено; во втором формула была выполнена и дала нейтральный вклад.

# Модуль 3. BG range и интерполяция

Алгоритм использует:
- `bg_off = T + 10 - G`;
- `x = 100 - bg_off = G - T + 90`.

Здесь G — синтетическая текущая глюкоза, T — синтетическая цель, в согласованных единицах исходного алгоритма.

Опорные точки кривой:

| x | y |
|---:|---:|
| 50 | -0.5 |
| 60 | -0.5 |
| 80 | -0.3 |
| 90 | -0.2 |
| 100 | 0.0 |
| 110 | 0.0 |
| 150 | 0.5 |
| 180 | 0.7 |
| 200 | 0.7 |

После линейной интерполяции y умножается на lower weight при x <= 100, иначе на higher weight. Вклад входит в `bg_ISF = 1 + interpolate(x)`.

### Учебный пример

Только для арифметики, не для настройки терапии:

- T = 100;
- G = 80;
- x = 80 - 100 + 90 = 70;
- между x=60 (y=-0.5) и x=80 (y=-0.3);
- линейная интерполяция при x=70 даёт y=-0.4;
- при условном учебном lower weight 0.5 вклад = -0.2;
- условный `bg_ISF = 1 - 0.2 = 0.8).

Проверка интерполяции:
`y = y0 + (x - x0) / (x1 - x0) * (y1 - y0)`.

### Задания

1. Рассчитать y при x=85.
2. Рассчитать y при x=120.
3. Показать, почему при x=100 вклад равен нулю независимо от конечного lower/higher weight.
4. Сравнить x=99 и x=101: указать, какая ветвь веса выбирается.
5. Объяснить, почему нельзя переносить lower weight на верхнюю ветвь.

# Модуль 4. Ускорение и торможение

Ключевой gate качества fit: `corrSqu >= 0.9`. Если условие не выполнено, фактор ускорения/торможения не должен применяться как обычный валидный вклад.

В коде используется:
- `fit_share = 10 * (corrSqu - 0.9)`;
- множитель ускорения имеет базовую форму `1 + bgAcceleration * cap_weight * selected_weight * fit_share`.

На выбор веса и знак влияют направление ускорения и контекст относительно цели. В коде есть дополнительные ограничения: например, изменение cap при определённом контексте ниже цели и логика торможения при прогнозируемом снижении.

### Задания

1. Для corrSqu=0.89 определить, проходит ли gate.
2. Для corrSqu=0.90 вычислить fit_share.
3. Для corrSqu=0.95 вычислить fit_share.
4. Объяснить, почему положительный fit_share сам по себе не определяет знак итогового изменения ISF.
5. Найти в коде условия выбора acceleration weight и braking weight; выписать их отдельно.

Не считать упрощённую формулу полной моделью: окончательное поведение определяется всеми условиями и ограничениями в исходнике.

# Модуль 5. Postprandial и duration

### Postprandial

Упрощённая форма множителя:
`pp_ISF = 1 + max(0, delta * pp_ISF_weight)`.

Фактор имеет gates, в частности связанные с `bg_off <= 0`, `shortAvgDelta >= 0` и проверкой среднего уровня относительно цели. При невыполненном gate формула не применяется.

### Duration

Фактор пропускается, если длительность меньше 10 минут или среднее значение duration не выше цели. В активной ветви используется разность среднего уровня и цели, длительность и `dura_ISF_weight`.

### Задания

1. Найти в исходнике полный список gates PP.
2. Найти полный список gates duration.
3. Составить по два синтетических сценария: gate пройден и gate не пройден.
4. Для каждого сценария объяснить, фактор пропущен или вычислен.
5. Проверить, как ранняя ветвь BG range при `bg_ISF < 1` меняет дальнейший путь расчёта.

Минимальная матрица:
1. Все веса нулевые.
2. Только lower weight ненулевой.
3. Только higher weight ненулевой.
4. x=100 — нейтральный узел кривой.
5. Fit ниже порога 0.9.
6. Fit ровно 0.9.
7. PP gate закрыт.
8. PP gate открыт.
9. Duration ниже 10 минут.
10. Duration выше 10 минут, но среднее не выше цели.
11. Duration gate открыт.
12. BG range ветвь даёт значение ниже 1 и активирует ранний выход.
13. Итог ограничивается autoISF_min.
14. Итог ограничивается autoISF_max.

## Правила качества

- Один тест — одна проверяемая гипотеза, если только интеграционный тест явно не проверяет взаимодействие.
- Не менять несколько весов одновременно в тесте, предназначенном для изоляции одного веса.
- Для нейтральности сравнивать с базовым сценарием при тех же остальных входах.
- Проверять границы непосредственно ниже, на границе и выше.
- NaN и Infinity проверять отдельно от обычных значений вне диапазона.
- Не путать UI validation, sanitization, алгоритмические gates и итоговые hard limits.
- Успешные unit tests не равны клинической валидации.
- Успешная сборка APK не равна проверке UI на эмуляторе.
